# Замкнутость компактного состояния для порядкозависимых статистик

## Область утверждений

Ниже рассматривается не всякое возможное сжатое представление временного ряда,
а конкретный класс состояний: одно состояние описывает один плотный интервал
ключей, хранит фиксированномерные числовые сводки и не более `L` первых и
последних наблюдений. Единственная точная операция композиции такого состояния —
конкатенация двух соседних интервалов.

## Утверждение 1. Незамкнутость при произвольном дереве merge

Семейство однодиапазонных prefix/suffix-состояний не замкнуто относительно
произвольного порядка слияния частичных состояний, допустимого для обычной
агрегатной функции ClickHouse.

### Доказательство

Пусть корректный итоговый ряд содержит три наблюдения с ключами `1`, `2`, `3` и
значениями `v_1`, `v_2`, `v_3`. Обычный reducer имеет право сначала выбрать
состояния для ключей `1` и `3`. Эти интервалы не соседние.

Если операция отвергает такое слияние, корректный набор входных данных может
завершиться ошибкой только из-за выбранной reducer-ом формы дерева. Следовательно,
это не полный контракт обычной агрегатной функции.

Если операция всё же заменяет два фрагмента одним внешним интервалом `[1, 3]`,
состояние либо ошибочно объявляет интервал плотным, либо должно отдельно помнить
дыру и оба несмежных фрагмента. При последующем поступлении ключа `2` его нельзя
добавить обычной операцией `mergeAdjacent`: он находится внутри уже записанного
внешнего интервала.

Для суммы переходов первого лага точный результат равен

```text
v_1 * v_2 + v_2 * v_3.
```

Промежуточные состояния `[1]` и `[3]` не содержат ни одного из этих переходов.
После появления `[2]` требуется создать сразу две внутренние границы, что нельзя
выразить конкатенацией одного левого и одного правого плотного диапазона.

Контрпример масштабируется: reducer может сначала объединять все нечётные ключи,
а чётные предоставить позже. Для точного продолжения придётся хранить
неограниченно много разрозненных интервалов либо сами внутренние наблюдения. В
худшем случае объём такого состояния растёт как `Omega(n)`. Следовательно,
ограниченное однодиапазонное prefix/suffix-состояние не замкнуто относительно
произвольного дерева merge. □

Утверждение намеренно узкое. Оно не доказывает невозможность любого алгоритма
сжатия и не запрещает приближённые методы; оно фиксирует несовместимость именно
ограниченного однодиапазонного состояния с обычным произвольным merge-контрактом.

## Утверждение 2. Корректность при слиянии соседних диапазонов

Пусть `A` и `B` — плотные диапазоны одной серии с одинаковой конфигурацией, причём
последний ключ `A` непосредственно предшествует первому ключу `B`. Для заданного
максимального лага `L` состояние хранит общие центрированные моменты, сводки пар
для каждого лага, первые и последние `min(L, n)` значений и необходимые
префиксные статистики KPSS. Тогда `mergeAdjacent(S(A), S(B))` восстанавливает то
же математическое состояние, что и прямой упорядоченный проход по `A || B`.

### Доказательство

Для каждого лага `h <= L` все пары в `A || B` однозначно делятся на три
непересекающиеся группы: пары внутри `A`, пары, пересекающие границу, и пары
внутри `B`. Первую и третью группы уже содержат частичные состояния. Каждая
граничная пара использует не более `h` последних значений `A` и первых значений
`B`, поэтому полностью восстанавливается из suffix/prefix-буферов. Общие моменты,
буферы и KPSS-статистики объединяются по тем же границам. Значит, результат
одного соседнего слияния совпадает с прямым проходом. Индукция по бинарному дереву,
в котором каждое внутреннее слияние соединяет соседние интервалы, даёт тот же
результат для всего ряда. В точной арифметике равенство строгое; в реализации на
`Float64` сравнение выполняется с масштабно-зависимым допуском. Память одного
состояния составляет `O(L)`. □

## Реализованная граница

Автономный файл `coursework/comparison/standalone_cpp/standalone.cpp` реализует
описанный усиленный контракт: добавление только следующего ключа, слияние только
соседних плотных диапазонов, проверку несовместимых диапазонов, сериализацию и
финализацию ACF, Ljung–Box, Durbin–Watson, AR(1) и KPSS. Это сравнительный
прототип, а не зарегистрированный SQL aggregate и не оператор планировщика.
